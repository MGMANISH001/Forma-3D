FORMA3D is a personal project: a complete made-to-order e-commerce experience where every product can be re-designed live in 3D. It exists so I could practice real full-stack skills — API design, pricing logic, WebGL rendering and responsive UI — and end up with something worth clicking through.

Why I built it

Most tutorial projects stop at a to-do list. I wanted the opposite: a project with the messy, interesting problems of a real store — products made of configurable parts, prices that must be computed and verified on the server, and a shopping experience that has to feel good on a phone held in one hand.

The 3D angle came from wanting to understand WebGL properly instead of treating it as a black box. Every model in this shop — the lounge chair, the headphones, even the candle flame — is generated procedurally in JavaScript. No downloaded meshes, no model files: geometry built from primitives, lathes and tori, then lit with PBR materials and a soft-box environment.

The constraint I set for myself: no frontend frameworks and no build step. Plain HTML, hand-written CSS and vanilla JS talking to a Django REST backend. If a recruiter opens the folder, every line is readable and every file has a reason to exist.

The toolkit

Chosen deliberately small — the point was to understand every layer, not to assemble one.

Django 6 + DRF

Models, migrations, serializers, viewsets and validation. The catalog and orders apps expose a clean, filterable JSON API.

Pricing engine

A server-side module recomputes every quote: base price + per-part option deltas + engraving fee + shipping rules. The client never dictates a number.

Three.js / WebGL

Procedural geometry per product type, PBR material recipes, a PMREM environment for believable reflections, PCF soft shadows and orbit controls tuned for touch.

Vanilla JS architecture

Small single-purpose modules: API client, localStorage cart with change events, shared layout injection, one offscreen renderer that photographs products for thumbnails.

CSS design system

Design tokens, a warm minimal palette, a full dark theme, fluid type with clamp(), skeletons and reduced-motion support — all hand-written, ~1000 lines.

SQLite + seeding

A management command builds the whole demo catalog — products, parts, options, badges — so a fresh clone becomes a working store with one command.

What this project demonstrates

The skills below are the reason the project exists — each one is exercised by real, working code in the repository, not by a bullet point. Open any file it mentions and you will find the implementation.

  • REST API design — resource-oriented endpoints, serializer validation, meaningful error payloads
  • Trustworthy commerce logic — server-side quoting, order persistence, free-shipping thresholds
  • 3D graphics programming — procedural meshes, PBR materials, environment lighting, camera tweening
  • State management without a framework — an event-driven cart, URL-driven product selection, theme persistence
  • Responsive & mobile UI — mobile-first layouts, sticky purchase bar, touch gestures, 390px to 1440px
  • Accessibility practice — ARIA labels, focus-visible states, semantic HTML, reduced-motion paths
  • Performance hygiene — offscreen WebGL thumbnails, disposed contexts, clamped pixel ratio, lazy reveal
  • DX & packaging — one-command bootstrap, self-seeding data, a README a stranger can follow
